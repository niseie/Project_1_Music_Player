Part B

1. Playlist(I made my own doubly linked list)
    The playlist keeps the songs in order, which answer the question "what plays after this song?", and lets me remove any song 
    without searching it, this is because the library stores each song's node. With just a plain array, removing a song from the middle of the array 
    shifts every element later element, which is O(n), and finding the next song means first finding the index, which adds a lot of unnessary steps.
    I built my own node class instead of reusing Java LinkedList because linked list doesn't hand out it's internal nodes which would make remove(obj) have
    to search from the head, which comes at a cost.

2. Up next(ArrayDeque I reused)
    The upnext is a line of songs that I add the the back of queueLater, add to the front of queueNext, and take from the front.
    A deque makes all of those O(1) at both ends. With a plain array, adding or removing at the front is O(n) because every element shifts,
    and that would come at an extra cost every single time this runs. I reused ArrayDeque instead of building my own because it would save me the time 
    I would spend debugging the program.
